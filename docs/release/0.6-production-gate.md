# Notare 0.6 — Production Gate

The checklist that gates a 0.6 **production** release. Same policy as 0.5 (QA/release-gate,
2026-07-22): an RC may ship with *documented* known edge cases; **production may not ship with
any open `GATE: BLOCK` row.** Every row needs evidence per platform (Linux verified on
coruscant; macOS/Windows gated on Abhishek). RC path: `0.6.0-rc.n` (edge cases allowed) →
production (none).

Legend: ✅ pass (evidence) · ⚠️ RC-acceptable known edge case · ⛔ BLOCK (must clear before
production) · ▫️ not yet exercised on this platform.

**0.6's headline is P2P device-to-device sync.** The scope was deliberately narrowed to a
shippable subset: hub failover, blob-log GC, and the remaining unproven tables are explicit
non-goals, recorded in §F rather than left to look like oversights.

### Tables deliberately NOT enabled

Four are **proven unsafe**, not merely unproven — each duplicates the entity under concurrent
creation because the primary key is a locally-minted `crypto.randomUUID()` while the real
identity lives elsewhere. The `db-app` guard test pins all four verdicts.

| Table | Status | Real identity | Evidence |
|---|---|---|---|
| `humans` | ⛔ do not enable | `lower(email)` | §25.2 — duplicates on both write paths |
| `session_participants` | ⛔ do not enable | `(session_id, human_id)` | §25.2 |
| `calendars` | ⛔ do not enable | `tracking_id_calendar` | §26.2 |
| `events` | ⛔ do not enable | `tracking_id_event` | §26.2 — worst case: the duplicating write is the poller, so it fires per device automatically |

Three are **unused** — no live app write path, so there is no write pattern to model:
`daily_notes` and `session_attachments` (only `legacy_import.rs`), `entity_mentions` (nothing,
anywhere). §28.

Two remain **unproven and unattempted**: `chat_groups`, `chat_messages`. §25.1.

## B. Sync — runtime verification (**the one genuine BLOCK**)

| Item | Linux x86_64 | macOS | Windows | Evidence |
|---|---|---|---|---|
| `desktop` compiles with `--features sync` | ✅ | ✅ | ✅ | §22.6; now a required CI job (§24) |
| `cloudsync` builds from source | ✅ | ✅ | ✅ | §21.10–§21.17; required (§24) |
| Two-node CRDT convergence, real schema | ✅ | ▫️ | ▫️ | §17/§23/§25/§27 — **Linux only** |
| Three-node convergence over elected hub | ✅ | ▫️ | ▫️ | §15 — Linux only |
| E2E payload encryption invariants | ✅ | ▫️ | ▫️ | §18.3 |
| Real discovery (iroh relay + pkarr) | ✅ | ▫️ | ▫️ | §20.8 — manual, `#[ignore]`d, not in CI |
| App start/stop sync lifecycle | ✅ | ▫️ | ▫️ | `sync_lifecycle.rs` 4 tests — Linux only |
| **The sync stack has ever been EXECUTED** | ✅ | ⛔ | ⛔ | §22.8 — every macOS/Windows proof is `cargo check` |

⛔ **GATE: BLOCK.** Nothing has ever *run* the sync stack off linux/x86_64. `P2pAgent::start`,
the C socket layer in `network_p2p.c` (Winsock2 vs POSIX), and a real two-peer round trip are
compile-and-link proven only. The Winsock2 port has been *compiled* on Windows (§21.17) and
never *executed* anywhere.

Clearing this needs either a real integration test in CI or manual verification on
physical/VM hardware. It is the single largest known risk in 0.6 and it is not a code gap —
it is an untested-platform gap.

⛔ **GATE: BLOCK — packaged-install verification.** #154 fixed two defects that made installed
builds unlaunchable (the from-source extension resolved a compile-time `OUT_DIR` path that
does not exist on a user's machine; and a failed extension load panicked before tracing
existed, killing the process silently). The fix is compile-proven and regression-tested, and a
`desktop_test_build` ran green — but **that proves the build, not the install.** Installing an
MSI on a machine that has never seen the build tree is exactly the gap that produced the bug.
Gated on Abhishek.

## F. Explicit non-goals for 0.6 — deferred to 0.7

Recorded so they read as decisions rather than omissions.

- **Hub failover / election** (§15.2, §20.10) — the hub is a single point of failure with a
  static identity. Unbuilt.
- **Blob-log GC** (§15.2, §20.10) — the hub retains every blob forever. Unbuilt.
- **The 9 remaining disabled tables** — 4 proven unsafe (fix named in §25.4/§26.3), 3 unused,
  2 unproven.
- **`strstr`-based JSON parsing** in `network_p2p.c` (§12, §21.4) — production hardening for a
  typed codec, never touched.
- **No hostile-broker/peer test fixture** (§12) — nothing tests behaviour against a malicious
  or malformed peer.
- **Scheduled re-run of the `#[ignore]`d real-network discovery test** (§20.10) — a process
  gap; nothing catches an n0-side regression.
- **`templates` fresh-device re-seed** (§27.4) — a device joining an existing sync set replays
  the default-template seed and resurrects built-ins deleted elsewhere. Nodes converge, so it
  is a seeder bug, not a CRDT one — but enabling `templates` is what makes it cross-device. Fix
  belongs in the seeder (seed once per database behind a marker). **A reviewer may reasonably
  reverse the decision to enable `templates` because of this.**

## Summary — what blocks 0.6 production today

1. ⛔ The sync stack has never been executed on macOS or Windows (§B).
2. ⛔ No packaged install has been verified since the #154 packaging fix (§B).
3. ⛔ `main` has no required status checks, so the promoted CI jobs do not block merges (§E).
4. ⛔ Decision: whether `local-llm` enters `release.yaml` (§D).

Rows 1, 2 and 3 are gated on Abhishek — hardware, an install, and a repo setting. None is a
code change.
