# Notare 0.6 — Production Gate

The checklist that gates a 0.6 **production** release. Same policy as 0.5
(QA/release-gate, 2026-07-22): an RC may ship with *documented* known edge cases;
**production may not ship with any open `GATE: BLOCK` row.** Every row needs
evidence per platform (Linux verified on coruscant; macOS/Windows gated on
Abhishek). RC path: `0.6.0-rc.n` (edge cases allowed) → production (none).

Legend: ✅ pass (evidence) · ⚠️ RC-acceptable known edge case · ⛔ BLOCK (must clear
before production) · ▫️ not yet exercised on this platform.

## 0. What 0.6 is — and the re-scope that produced it

**0.6 was scoped as the P2P sync release. Sync is deferred to 0.7.** The ELv2
determination that cleared sqlite-sync as the CRDT engine was withdrawn on
2026-09-02 (`docs/LICENSE-NOTE.md`); SQLite Cloud's written reply denies use of the
custom network layer the whole transport is built on. The sync gate rows are carried
forward intact in **`docs/release/0.7-sync-gate.md`** — no evidence was discarded.

**Deferring cost no code.** `release.yaml:68,126` build `--features
gpu-vulkan,directml` and `gpu-vulkan`; `sync` is in neither and never was. The sync
stack has never reached a user.

### What that leaves — stated plainly

0.6 is a **small release**. Measured against `v0.5.2`, `main` carries 115 non-merge
commits, of which ~75 are sync and 14 are non-sync. Of those 14, exactly one is
user-facing: the trash view (`226ad741d`, contained in zero tags).

Everything else people sometimes associate with this cycle already shipped —
verified with `git tag --contains`:

| Feature | First shipped in |
|---|---|
| On-device diarization + voice recognition | **v0.4.0** |
| Hybrid search tab | **v0.5.0** |
| Action-items checklist UI | **v0.5.0** |
| Recording finalize-on-exit / orphan recovery / rename-hang (#101, #102, #105) | **v0.5.0** |

So 0.6's user-facing content is: the **trash view**, **signed + notarized macOS
builds** (§B — today's macOS builds are unsigned), the **recording-bar redesign**
(§E), and the **embedded local LLM** *if and only if* §D's shipping decision goes
that way. That is the honest inventory. If it is too thin to warrant a minor
version, `0.5.3` is the alternative and is a legitimate outcome of reading this
page.

## D. Embedded local LLM (#20 / PR #156)

Two decisions, deliberately kept apart.

**D1 — merge #156.** `+2152/-250` across 28 files, MERGEABLE, not draft, default-OFF
at every level; a default `cargo check -p desktop` resolves none of it. Merging
ships nothing to users. Low risk, do it.

| Item | Status | Evidence |
|---|---|---|
| Default builds unchanged | ✅ | Feature default-OFF at every level |
| Compiles, Linux (+ Vulkan) | ✅ | `local_llm_gate_linux` |
| Compiles, macOS / Windows (+ Vulkan) | ▫️ | `local_llm_gate_{macos,windows}` — **PROVISIONAL**, never run on a real runner |
| Mid-stream panic reported, not dropped | ✅ | Audit finding fixed — a discarded `JoinHandle` silently truncated the SSE stream |
| Unit tests | ✅ | 14 passed / 2 ignored across `local-llm-core`, `local-model`, `local-llm-llama` (per PR; re-run before merge, do not take on trust) |

**D2 — put `local-llm` in `release.yaml`.** *This* is "ship the local LLM", and it
turns the PR's honestly-declared caveats into gate rows. #20 stays open until this
call is made.

| # | Item | Status | Why it blocks shipping |
|---|---|---|---|
| 1 | `crates/local-llm-core/src/server.rs` unit coverage | ⛔ | **474 lines, zero unit tests** — the PR calls it "the weakest part of this lane". SSE streaming, the backpressure-bounded channel, and the context-window stop condition are covered only by an `#[ignore]`d E2E test. `AppState` holds a concrete `Arc<Mutex<LlamaLlmModel>>`; a trait over the single `generate` call makes it testable |
| 2 | Executed on macOS / Windows | ⛔ | All three gate jobs are `cargo check`. Nothing has *run*. **Same class of gap that defers sync** (`0.7-sync-gate.md` §B) — consistency says it blocks here too |
| 3 | Release build cost measured | ⛔ | llama.cpp C++ compile on every release build, plus binary growth. Unquantified |
| 4 | **Model availability** | ⛔ | All three GGUFs download from `hyprnote.s3.us-east-1.amazonaws.com` — **Fastrepl's** bucket, not ours (`crates/local-model/src/lib.rs:26-37`). Verified live 2026-09-02 (HTTP 200, `Last-Modified: 2025-08-18`), but per `docs/LICENSE-NOTE.md` Fastrepl renamed and moved to a separate closed product. Shipping a feature whose weights sit on a third party's S3 bill is an availability dependency we do not control. Mirror them, or repoint Llama/Gemma at their redistributable HF originals |
| 5 | Promote the 3 `local_llm_gate_*` CI jobs | ⛔ | Currently PROVISIONAL/non-blocking; same evidence bar the sync jobs used (green across a few PRs, then into `ci`'s `needs:`) |
| 6 | `local-llm-cuda` | ⚠️ | Compile-checked nowhere. Either cover it or state explicitly that it is unshipped (current posture matches `voxtral-cuda`) |
| 7 | Real-model E2E | ⚠️ | `crates/local-llm-core/tests/real_model.rs` is `#[ignore]`d, needs a ~1GB GGUF + `HYPR_LLM_GGUF_PATH`, not in CI, nothing re-runs it |

Model **integrity** is handled — CRC32 per model (`crates/local-model/src/lib.rs:47-53`),
consistent with ADR-0002. It is **availability** that is unguarded (row 4).

**Recommended sequencing:** merge D1 now; treat D2 as a row that clears only if the
macOS/Windows execution session in §A happens. If it slips, 0.6 ships without the
LLM and it rides in 0.6.1 as a one-line workflow change.

⚠️ **Two scope notes, recorded rather than resolved silently.**

1. Issue #30's reference images (waveform + red *playhead* + `NEW RECORDING #256`)
   describe a session-**review** bar. `DESIGN-DIRECTION.md` §3b's Bar is the live
   floating widget and has **no waveform**. These are different surfaces. The
   reference `.webp` files are not in the repo, so implementation follows the
   written spec; the review bar is called out as separate work.
2. §4 ranks the floating widget priority **5**, explicitly *"ship after transcript
   so states are real"* — and the transcript pass (priority 2) has not happened.
   Building the bar first designs its states against a surface that will change. A
   reviewer may reasonably prefer swapping #30 for the transcript pass.

## Summary — what blocks 0.6 production today

1. ⛔ **#19 macOS signing + notarization** (§B) — secrets + one `verify_macos_signing`
   dispatch. **Do first**: it is the precondition for row 2.
2. ⛔ **One macOS session and one Windows session** (§A) — clears most of the carried
   0.5 table, including three reliability rows that validate *already-shipped* code.
3. ⛔ **OS-wise regression report** (§A) — never started.
4. ⛔ **`main` has no required status checks** (§F) — repo setting.
5. ⛔ **Decision: does `local-llm` enter `release.yaml`** (§D2), and if so, rows D2.1–D2.5.
6. ⚠️ **Is 0.6 a minor version at all** (§0) — one unreleased user-facing feature plus
   signing. `0.5.3` is a legitimate reading.

Rows 1–4 are gated on Abhishek: hardware, an install, and a repo setting. None is a
code change. Row 5 is a decision plus real work. Row 6 is a judgement call that this
page exists to inform rather than make.
